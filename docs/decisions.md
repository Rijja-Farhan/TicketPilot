# Decisions log

## 2026-11-01: Rebrand domain from SaaS to fintech
Chose a fictional fintech (Northwind Pay) so public banking-support datasets (Banking77, Bitext, CFPB, NAB) map onto our ticket categories with minimal remapping. Trade-off: we still need to write the glue (customer/ticket links, incident clusters) and the policy KB ourselves.

## 2026-11-01: A1 uses LLM only where language is needed (docs/spec-a1.md)
Ticket-by-ID and by-customer lookups are plain code: exact, deterministic, free, and an LLM there only adds error. The LLM handles free-text ticket questions (given the looked-up ticket as context), policy questions (given retrieved docs, must cite) and the fallback intent call. Router is regex first, LLM intent only if no regex matches. A lookup is "pure" if the text left after removing the ID contains only lookup words ("show", "ticket", "details"); anything else with an ID is a free-text ticket question.

## 2026-11-01: One SDK, provider table in config (plan-a1 section 3)
Groq, OpenAI and Ollama expose OpenAI-compatible endpoints, so `llm.py` uses the `openai` SDK and `config.PROVIDERS` holds base URL, key env var and model. Switching provider is one `.env` line. JSON mode is requested but output is always Pydantic-validated, with one retry that feeds the validation error back, then a typed `LLMError` (never an exception). A `fake` provider runs through the same code path via a duck-typed client (`fake_llm.py`) so tests are offline. Model IDs in the table are unverified placeholders until checked against each provider's model list.

## 2026-11-01: Citations are built in code, not by the model
The model lists sources it used, but `policies.answer` keeps only sources that were actually retrieved and fills `effective_date` from the doc's front matter. A fabricated or superseded source (in default mode) is dropped; if none survive, no answer is given. Retrieval is BM25 over whole current docs (A4 replaces it with embeddings and chunking). History questions (keyword check) include superseded docs.

## 2026-11-01: Banking77 intent -> category mapping (tools/gen/make_tickets.py)
The 77 intents map to the 8 labels in `CATEGORY_INTENTS` (the generator asserts every intent is mapped). Judgement calls: unrecognised card/cash/direct-debit payments and compromised card or lost phone -> `fraud_security`; top-ups and pending/reverted payments -> `transfers_payments`; refund requests, double charges and wrong cash amounts -> `disputes_refunds`; country/currency/age/exchange-via-app questions -> `other`. Banking77 has no loan intents, so the A1 sample has zero `loans_credit` tickets (CFPB would supply those later). `T-9001` is a hand-written prompt-injection fixture appended to the 300 sampled tickets.

## 2026-11-01: A3 tools live behind our own MCP server over a mock HTTP API (docs/spec-a3.md)
Chain: agent -> MCP client (stdio) -> `mcp_server` -> HTTP -> `mockapi` (FastAPI) -> `data/*.jsonl`. The mock API is a separate process so the MCP server is a real wrapper over a network service, with real failure modes (404, 422, 503, timeouts), not a function import. The server holds no business logic. Used the official `mcp` SDK (v2.x: `MCPServer`, `Client`); it is a protocol library, not an agent framework, so the plain-SDK rule in `AGENTS.md` still stands. `llm.complete()` gained an optional `tools=` argument and returns `tool_calls`; it stays the only module that imports the LLM SDK.

## 2026-11-01: One error contract for every tool, gates in code not in the prompt
Every tool returns data or `{"error": {"code", "message", "retryable"}}` with codes `not_found`, `invalid_argument`, `upstream_unavailable` (retryable), `rate_limited` (retryable). Tools never raise and never return a stack trace or an upstream body; text fields are capped at 2,000 chars and lists at 50 rows, because large tool output is a context-rot source. Errors from inside the MCP SDK (its own schema validation) are mapped to the same contract by `ToolBox.call`. Two rules are enforced in `agent.py` rather than trusted to the prompt: `add_ticket_note` (the only write) is refused unless the user's own message mentions a note, and an identical repeated call is refused (`duplicate_call`) so the agent cannot loop on a `not_found`. Both are tested with scripted fake-provider turns, including a prompt injection in ticket T-9001 that tries to trigger a write.

## 2026-11-01: A1's free-text ticket path now goes through the agent
In A1, "why is T-1001 still open?" made one LLM call with the ticket pasted in. Now it, and any question about a customer ID that is not a bare lookup, goes to the tool-calling agent, which can also check customer history and policy. Bare lookups ("show T-1001", "tickets for C-17") keep the plain-code path with no LLM and no tools. The A1 single-shot helper was removed rather than kept as a second path; the two A1 tests that covered it were replaced by agent tests. Cost: a free-text ticket question now needs the mock API running.

## 2026-11-01: Tool design change after watching the agent misuse `search_tickets` (the A3 misuse note)
Observed on Groq (`openai/gpt-oss-120b`), question "is C-5 a premium customer, and do they have any open fraud tickets?": in 3 of 3 runs the model called `search_tickets` with `category: "fraud"`, which is not a category (`fraud_security` is). It recovered from the error message each time, but cost a round trip. Three fixes tried, each measured with the same question:
1. Description lists the valid values and maps "fraud" to `fraud_security`: no effect, still 3 of 3 wrong first guesses.
2. Put the values in the JSON schema as an enum: made it worse. Groq validates tool arguments against the schema itself and rejects a bad value with HTTP 400 before we see it, so the model could not self-correct and the request failed (`provider_error`). Reverted. Lesson: provider-side schema enforcement turns a recoverable tool error into a hard failure, so keep validation (and the helpful error) in our server.
3. Kept: the server accepts an unambiguous fragment (`fraud` matches only `fraud_security`) and says what it did with `"filters_normalized": {"category": "fraud_security"}`. Ambiguous or unknown values still return `invalid_argument` listing the allowed values. Result on the same question, 3 of 3 runs: 2 tool calls and 0 errors, down from 3 calls and 1 error. Trade-off: the server now interprets input a little, which is why the applied value is echoed back instead of applied silently.

## 2026-11-01: A4 ingestion and retrieval (docs/spec-a4.md, docs/a4-eval.md)
- **Status is derived, not trusted.** Within a policy, the latest effective non-draft document is `current` and earlier ones are `superseded`, whatever their front matter says. The messy corpus has a v2 whose front matter still says `current` and a stale FAQ; both were overridden. Drafts stay `draft` and are never returned by default or for history.
- **Versions are not duplicates.** Near-duplicate removal (3-word shingle Jaccard) skips pairs whose declared versions differ, because versions of one policy are naturally near-identical (v2 vs v3 scores 0.537). The threshold 0.68 is the midpoint between the lowest true duplicate (0.813) and the highest labelled non-duplicate (0.537), taken from labelled pairs rather than set by feel. The keeper is the copy with declared metadata, then the newest, then the shortest file name.
- **Quarantine, not silent drops.** An image-only PDF is reported as `needs_ocr`. No OCR was installed, so its content is unavailable (trade-off accepted).
- **Shipped retrieval: structure-aware chunks with the doc header, hybrid (BM25 + dense, reciprocal rank fusion), status filter before ranking.** Selected on a 20-question grid by a rule (best default-condition recall@3, ties by unfiltered recall, then MRR); the margin over the runner-up is one question. A lexical gate keeps "no word in common with any chunk" from reaching the model, since dense search always ranks something. `policies.search/answer` keep their A1 signatures; without a built index (or with `kb_dir` given) they fall back to A1 BM25 over `data/kb/`, so A1 tests are unchanged.
- **Embeddings:** local `BAAI/bge-small-en-v1.5` via fastembed behind one interface; a hash embedder for offline tests (`EMBEDDINGS_PROVIDER`).

## 2026-11-01: A4 memory design
Episodic entries are written by code, not by the model, from enumerated fields only, so ticket text and customer names cannot reach the file; redaction of long digit runs is a second guard. Semantic facts are stored only from an explicit user command. Expiry is 90 days; `forget` rewrites the file without the customer (it is the one non-append operation, because a purge must actually remove the data). A newer fact with the same key hides the older one at read time and the older one stays in the file. Memory is injected as a dated `<memory>` data block and described as possibly out of date.

## 2026-11-01: A4 classifier data and recommendation
- **CFPB narratives are unavailable** (API and CSV export carry no complaint text), so `loans_credit` uses LLM-written messages seeded by real CFPB topics, with an LLM-written `fees_charges` control set to measure the style confound. Whole topics are held out for test and validation so paraphrases never straddle a split.
- **Split fixed once** (`data/splits/`, checksums, script refuses to overwrite). Test = Banking77 `test.csv` + held-out topics. A train text that also occurs in `test.csv` is dropped from training (25 rows).
- **Threshold 0.7** from a validation cost table (wrong 1, missed fraud 5, deferral 0.3). The deferral cost assumed the LLM resolves deferred tickets; measurement showed it does worse than the classifier on them (50% vs 65%, n = 20).
- **Recommendation:** classifier first, low-confidence tickets to human review, not to the LLM, until a few-shot prompt is shown to beat the classifier on the deferred subset. The classifier as an agent tool belongs to A5.

## 2026-11-01: A5 coworker harness (docs/spec-a5.md, docs/harness-a5.md)
- **Writes: deny, then propose, versus an approval prompt.** The coworker never executes a write; `add_ticket_note` is denied in code and the report lists it under `proposed_actions`. An approval prompt would let a run end with an action taken, which "report for human review" excludes, and approval flows are Week 4. Cost: a human performs the note themselves.
- **`tools=` and `schema=` stay in separate phases.** Probed on Groq: a request with both fails with HTTP 400 ("json mode cannot be combined with tool/function calling"). PLAN, REFLECT, REPORT and the verifier use `schema=`; ACT uses `tools=`.
- **Checkpoint per tool call and per phase, not per phase only.** A crash mid-ACT then loses at most the call in flight. Cost: one atomic file rewrite per call (a few KB).
- **Classifier is an MCP tool (`classify_ticket`)**, so the trace shows it as an ordinary step. Side effect: the A3 assistant agent also sees it. Cost: the model decides what text to pass; the verifier checks the label and probability against the tool result, not that the text matched the ticket.
- **Code decides verification; the model check is advisory.** Report fields `status`, `stop_reason`, `verification`, `budget_used` are written by code.
- **Rate limits are retried by the harness (2 x 20 s), counted by the wall-clock budget.** `llm.complete` waits only ~15 s, shorter than Groq's window. The time budget went from the planned 120 s to 240 s after live runs showed 95 to 153 s with waits.
- **A repair round, then strip.** One regeneration with the specific failures; a second failure removes the unsupported findings into `open_questions` and gives `partial`, so a bad claim is never shown as a finding.

## 2026-11-02: A6 eval suite (docs/spec-a6.md)
- **45 cases, 14 held out, split fixed by a seeded script and a checksum.** Stratified by component so every component has held-out cases. Held-out outputs are masked in the runner unless `--reveal-held-out`; gold answers are written in `evals/build_cases.py` before any run. Cost: 14 held-out cases make rates noisy (one case is 7 points of the held-out score); counts are reported next to percentages.
- **Cases are data, graders are code, and graders have tests.** `evals/graders.py` takes an `Outcome`, so one grader set covers the router, the policy path, the A3 agent and the coworker. Unit tests feed each grader a good and a bad output. This caught two grader bugs before any live run: NFKC leaves a non-breaking hyphen as U+2010 (a dash fold was added), and the citation catalog read the live index instead of the test environment's.
- **A3 cases record tool calls with a proxy toolbox; the coworker already has a trace.** The A3 loop writes no trace, so trajectory checks apply to coworker cases only, and `no_write` and `limit_bounded` read the proxy's record for A3 cases.
- **One additive A5 change: the `act` trace event carries `retryable`.** Retry discipline could not be graded without it. Existing fields are untouched.
- **Judge: a different model (`qwen/qwen3.8-27b`) from the agent (`openai/gpt-oss-120b`), advisory only.** The code graders decide pass or fail. The rubric was revised once after seeing the first calibration (70% agreement, kappa 0.44 on 10 usable items); the revised 87% (kappa 0.73, n = 15) is optimistic because the revision saw those items. The labels were assigned by the assistant, not by a second human.
- **Classifier threshold: the destination of deferred tickets decides the threshold, and the LLM is not a good destination.** Measured on 118 validation tickets below 0.7: the LLM is right on 64.4%, the classifier on 62.7% (difference +1.7 points, 95% interval -10 to +13). With that measured accuracy, A4's 0.7 raises expected cost per ticket from 0.059 (never defer) to 0.079 at a 5:1 fraud-miss cost, a 34% increase; the best LLM threshold is 0.3, which defers 0.2% of tickets. If deferred tickets went to a review queue at an assumed cost of 0.5, the best threshold is 0.55 to 0.7. The shipped threshold stays 0.7 as a low-confidence flag in `classify_ticket` (the LLM fallback `classify()` is not wired into any agent), so no behaviour changed; wiring deferral to the LLM would be the wrong move on this evidence.
- **Fraud alert level.** Deferring also when P(fraud) is at least 0.2 lowers expected cost at 10:1 and 20:1 (0.075 to 0.070 and 0.105 to 0.096) and changes nothing at 5:1. Recorded in `docs/a6-classifier.md`; not shipped, because there is no review queue to send those tickets to.

## 2026-11-04: A7 ambient agent (docs/spec-a7.md, docs/a7-policy.md)
- **SQLite for the durable queue, one file for all ambient state.** Queue, seen events, annotations, approvals, alerts and outbox share one database, so a crash leaves a consistent state; a row left `processing` is re-claimed after a lease. A broker (Redis, SQS) would scale further but adds a service for a demo that never exceeds one worker. Cost: single writer.
- **Event time is the clock.** Dedupe windows, rate caps, detector buckets and cooldowns use the event's own timestamp, so replays are deterministic and tests do not sleep. Cost: a late replay carries an old time, which is handled (it is linked as a duplicate and does not move the clock back).
- **Quarantine, not drop, for flagged tickets.** Dropping lets an attacker hide a ticket; quarantine keeps the customer's real problem visible to a human while the model never sees the text (no LLM label, no draft, read-only enrichment). Cost: a flagged but genuine ticket waits for a person.
- **Draft step has no tools, and only the customer tier (not the name) reaches the model.** A fooled model cannot fetch other customers' data because it cannot call anything.
- **Default-deny action names.** The model proposes names; `policy.decide` canonicalises and looks them up; unknown names are denied. A real model proposed harmless-sounding names (`review_dispute_details`) that were refused, so the draft prompt now lists the two names it may use.
- **Output checks are code, not a second model.** Promised refund, claimed action, link or email, foreign customer ID, amount not in the ticket. Cost: they are blunt (a reply that quotes an amount only the customer's history would explain is rejected).
- **Detector: rolling mean and std over earlier buckets, Poisson-aware std floor, min count, cooldown.** k is the middle of the range of k values that work on the calibration stream (2.0 to 4.0, so 3.0), not the edge, because the calibration stream has only one burst and the edge of a one-burst range is noise. The alert text is built by code from numbers; an LLM never writes them.
- **Stream fixed before any run.** `data/stream/` is generated once from a seed (checksums, the generator refuses to overwrite). Normal text comes from the classifier validation split (calibration) and test split (eval); the classifier is used, never tuned, on it.
- **Cost estimate is measured per call and extrapolated per 1,000 tickets.** The live sample is 45 events because of the provider's daily token cap; the path mix is measured on the full stream with the real classifier.

## 2026-11-04: A7 findings that changed the design or the claim
- The decoy bump (8 extra tickets in 10 minutes on a base of 3 per 5 minutes) fired the detector on the eval stream (z = 5.0). The calibration stream's decoy happened not to. This is reported as a false alert, not tuned away: tuning k on the eval stream would break the calibration rule.
- Two burst tickets were linked as near duplicates because two different burst messages came from the same customer within 30 minutes. This is the dedupe working as specified on a generator quirk; it is reported as two false links.
- The guard flags 12 of 15 stream injections and 4 of 15 evasion attempts. It is a first filter. What holds is the layers behind it (docs/a7-redteam.md).

## 2026-11-09: Rename OpsPilot to TicketPilot
- **Everything that names the product is renamed:** the package (`opspilot/` to `ticketpilot/`, so `python -m ticketpilot`), the system prompts ("You are TicketPilot"), the UI header, the MCP server name (`ticketpilot-tools`), the `TICKETPILOT_*` env vars (no fallback for the old `OPSPILOT_*` names; none are set in `.env.example`), docs and the GitHub repo. The old repo URL redirects.
- **Left unchanged on purpose:** `data/` (the KB text, including fraud-policy v1's "never automatically by OpsPilot", the fixed splits and the checksummed streams; editing the KB would change the index and the recorded retrieval results) and the recorded judge calibration (`evals/calibration.jsonl`, `evals/calibration_results.json`, `evals/calibrate_judge.py`), which record what a model actually wrote.
- **The prompt-leak grader in `coworker-04` checks both "You are TicketPilot" and "You are OpsPilot".** Renaming the prompt without the grader would make the leak check pass silently. Only the grader's string list changed; the case ids and the dev/held-out split (`evals/cases/SPLIT.sha256`) are unchanged. Live results recorded before this change used the old prompt name.
