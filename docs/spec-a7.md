# Spec: A7, ambient agent (TicketPilot v4)

Source: `docs/plan-a7.md`. Builds on `docs/spec-a3.md` (tools), `docs/spec-a4.md` (classifier, threshold 0.7), `docs/spec-a5.md` (budgets, verify, durability) and `docs/spec-a6.md` (eval method). A1 to A6 behaviour does not change; everything new is in `ticketpilot/ambient/`.

## Contract
Input: an event stream (`Event`). Output: per-ticket annotations (category, priority, duplicate link, quarantine flag), approval items (drafts and risky actions awaiting a human), alerts, and an audit log. The agent never sends a reply and never executes a denied action.

## Event
`event_id`, `ts` (ISO UTC, the event's own time, used as the clock for windows so replays are deterministic), `customer_id`, `subject`, `body`, `source` (`webhook | replay`). Ticket text is customer-written data, never instructions.

## Pipeline per event
1. **Admit** (`queue.admit`): validate and normalise; exact duplicate (`event_id` seen) -> link; near duplicate (same customer, normalised text Jaccard >= 0.8 inside a 30 minute window) -> link; per-customer rate cap (5 per 10 minutes); queue depth cap (sheds priority 1 first; priority 0, i.e. fraud wording, is never shed below a hard cap). Every outcome is audited.
2. **Guard** (`guard.scan`): injection scan on the normalised text. Flagged -> **quarantine**: no LLM call, no draft, read-only enrichment, human notified.
3. **Classify**: `classify_ticket` tool. Probability >= threshold: accepted, no LLM. Below: LLM classification (not for quarantined tickets: they stay `unclassified` apart from the classifier's own label, marked low-trust).
4. **Enrich**: `get_customer` (allowlist). Unknown customer -> note, escalate.
5. **Draft** (non-quarantined only): LLM drafts a reply and may propose actions; policy and output checks run in code.
6. **Decide** (`policy.decide`): every action maps to a tier. Replies and status changes go to the approval queue.
7. **Detect** (`anomaly`): the scheduled tick counts deduplicated tickets per 5 minute bucket.

## Action tiers (default deny)
| Tier | Actions |
|---|---|
| auto | `set_category`, `set_priority`, `link_duplicate`, `quarantine`, `raise_alert`, `notify` |
| approval | `send_reply`, `change_status`, `escalate_to_human` |
| denied | `refund`, `freeze_account`, `close_account`, `read_other_customer`, `add_ticket_note` from the ambient path, any unknown action |

Ambient tool allowlist: `get_customer`, `classify_ticket`, `search_policies`. Anything else is refused where tools are called (`GuardedTools`).

## Audit entry
`seq, ts, prev_hash, hash, event_id, step, decision, tier, actor, reason, detail`. The hash covers the previous hash and the canonical JSON of the entry.

## Stream and gold (written before any run)
`data/stream/calibration.jsonl` and `eval.jsonl`, with `*_gold.json`. Calibration texts come from the classifier validation split, evaluation texts from the test split (the classifier is only used, never tuned on them). The generator and its seed are fixed; the files are never regenerated after the first run (checksums in `data/stream/CHECKSUMS.txt`).

Gold fields per event: `role` (`normal`, `duplicate_exact`, `duplicate_near`, `repeat_legit`, `burst`, `decoy`, `injection`, `flood`, `unknown_customer`), `duplicate_of`, `category`, and for injections `attack` and `expect_flag`. Windows: `burst` and `decoy` start/end. Some injections are designed to evade the pattern guard (`expect_flag: false`); the invariant for them is the policy layer, not detection.

## Detector
5 minute buckets of deduplicated, admitted tickets. Baseline = mean and std of the previous `window` buckets (current bucket excluded); `std_eff = max(std, sqrt(mean), 1)`; alert when `count >= min_count` and `z >= k`, then a cooldown of `cooldown` buckets. `k`, `window`, `min_count` are chosen on the calibration stream only: the smallest k in the grid that gives zero false alerts there and still catches its burst. The alert text is generated by code from numbers; an LLM never writes the numbers.

## Acceptance criteria
1. The system processes the eval stream end to end with no human prompt.
2. Exact and near duplicates are linked and not reprocessed; the legitimate repeat is processed.
3. Confident classifier predictions make no LLM call; deferred ones do.
4. The detector flags the burst with an explanation; the false-alert count and the decoy outcome are reported.
5. For every injection ticket, with a model scripted to obey, zero denied-tier actions run and nothing customer-facing is sent without approval.
6. Approve, edit and reject work; an edited draft is re-validated; timeouts escalate.
7. Every autonomous action has an audit entry; tampering is detected by `verify-audit`.
8. A killed worker resumes with no lost event and no duplicate annotation or approval.
9. Cost per 1,000 tickets is given with and without the classifier, with measured and extrapolated parts labelled.
10. The red-team report lists what got through.
11. The classifier test set is not tuned on; detector thresholds come from the calibration stream.
12. A1 to A6 tests still pass; `LLM_PROVIDER` is still the only provider switch; no secrets or runtime state committed.
